## Adjustment 1 — Reorder P0: invite acceptance first

Implement in this order:

1. **Invite acceptance** (flow 3): rich squad preview on private links
   ("🎿 Ski Crew · 4 members · invited by Maya" before signup, compact
   banner persisting through login/signup) + auto-accept after auth
2. **Trip interaction overhaul** (flows 5, 7, 8): replace the `runMut`
   whole-screen busy pattern with optimistic updates — votes (haptic +
   spring animation + voter avatar stack), packing check-off (instant
   strikethrough + haptic, revert on error with toast), StopSheet quick-add
   with "Suggest" / "Add to plan" action buttons
3. **Day-of Home takeover** (flow 9): live hero variant when a plan is
   today/in-progress — countdown, one-tap location to maps, today's
   itinerary stops for trips
4. **Event creation** (flow 4): progressive disclosure (title + date +
   squad above the fold, rest behind "Add details") + smart defaults
   (next Saturday 7pm, most-recent squad preselected)
5. **"Needs you" row on Home** (flow 12): pending RSVPs, open stop votes,
   unanswered availability polls as one-tap deep links
6. **First-member-joined celebration** (flow 2)

Rationale for the reorder: invite acceptance determines whether new users
get into the app at all — for soft launch, that outranks polish for
existing users.

## Adjustment 2 — Auto-accept must route through the consent/cap logic

The auto-accept-after-auth change (item 1 above) must integrate with the
squad-consent fix from the July 5 remediation:

- Tapping an invite link IS explicit intent, so auto-accept is fine — but
  it must still consume the user's squad-cap slot through the same
  accept-consumes-cap path as a manual accept, not bypass it
- If the user is already at their 2-squad cap, do NOT silently fail or
  silently join: show the standard upgrade prompt with the squad preview
  context ("Upgrade to join 🎿 Ski Crew")
- Verify a declined/abandoned signup from an invite link leaves no residual
  membership or pending-invite state

## Adjustment 3 — Verify name-field assumptions before the signup collapse
