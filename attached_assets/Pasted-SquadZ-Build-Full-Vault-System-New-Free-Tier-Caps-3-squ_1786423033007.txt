PART 2 — New free-tier caps (server-enforced)

Change the free-tier limits:

Squads: up to 3 (was 2)
Trips/events: up to 3 total combined (was 5) — still trips + events combined in one count, still the rolling 12-month window, still the append-only ledger mechanism (just the number changes 5→3).

Counting rules (this is the important logic — implement precisely):

Created a trip/event → counts (always, even if later cancelled/deleted — matches existing anti-abuse behavior; a user can't create-cancel-repeat to dodge the cap).
Joined/accepted a squad or trip/event → counts.
Joined then left → STILL counts (the slot is not returned — prevents leave/rejoin gaming). Match the current squad-leave behavior which already works this way.
Invited but not accepted → does NOT count. An outstanding invitation the user hasn't accepted must not consume a slot. Confirm this is handled correctly for both squads and trips/events.

Existing over-limit users (grandfather, don't punish):

Users who currently exceed the new limits (e.g. an account with 4 plans under the old cap of 5) must NOT lose access to their existing squads/plans. They keep everything they have, but cannot create/join NEW ones until they're back under the new limit. The enforcement logic must handle "already over" gracefully (no errors, no data loss, no hidden content) — it blocks new creation/joining, not existing access.

Enforcement must be server-side (the source of truth), with the client display matching. Confirm all entry points that create/join squads and plans route through the server-side check.

PART 3 — Transparency UI
Count display — show the user their current usage on both limits, e.g. "2 of 3 squads" and "1 of 3 trips/events used." Place these where a user encounters the limits (creation screens, profile, wherever natural).
Info "ⓘ" button next to each count — tapping it opens a clear, plain-language explainer of what counts and how it's measured:
Squads: creating or joining a squad counts; leaving does not give the slot back; being invited (not yet accepted) doesn't count.
Trips/events: creating or accepting counts; cancelled/deleted still count if you created them; leaving doesn't give the slot back; invites you haven't accepted don't count.
Keep it clear and non-punitive in tone — the goal is the user understanding the system, not feeling nickel-and-dimed.
Free vs. Squadz+ comparison screen — update the app's existing "what's included" comparison (the paywall/upgrade screen and anywhere else it appears) to reflect: the new 3 squads / 3 plans free limits, and the vault features (personal vault as a Squadz+ benefit). Make sure every place that states the free-tier numbers is updated consistently — no screen left saying "5 plans" or "2 squads."
