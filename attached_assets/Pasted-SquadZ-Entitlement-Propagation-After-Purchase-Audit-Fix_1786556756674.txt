SquadZ — Entitlement Propagation After Purchase (Audit → Fix)
Problem observed on device (TestFlight, iOS build 3)

A Squadz+ purchase completes successfully in the StoreKit sandbox, but the UI does not immediately reflect the upgraded entitlement. The tester had to navigate across several screens before gated surfaces updated. The purchase itself is fine — this is a state propagation bug, not a payment bug.

Working hypothesis (verify, do not assume): entitlement state is read via one-time fetches on screen mount rather than from a single global store fed by a live RevenueCat customerInfo listener. Screens already mounted at purchase time never re-read, so they show stale free-tier state until remount.

Do not treat this hypothesis as fact. Confirm or refute it in Phase 1 with actual file references.

PHASE 2 — IMPLEMENTATION (only after Phase 1 is approved)

These decisions are locked. Do not ask for alternatives.

Single global entitlement store. One source of truth for Squadz+ status for the whole app. Every gated surface reads from it. No screen performs its own independent entitlement fetch.
Live listener on app init. Register the RevenueCat customer-info update listener exactly once at app initialization. Every emission writes to the global store. Ensure the listener is cleaned up correctly and never double-registered across fast refresh, re-auth, or logout/login.
Optimistic-then-confirmed write on purchase. On a successful purchase result, write entitlement to the global store immediately from the returned customer info, without waiting for the server round-trip. Then reconcile against the server; if the server disagrees after reconciliation, the server wins.
Server reconciliation must tolerate webhook lag. If the client reads server entitlement immediately after purchase and the webhook has not landed, the client must not downgrade the user back to free. Retry with backoff (a small bounded number of attempts) before accepting a negative server answer. Log to Sentry when reconciliation resolves only after retry, so we can measure real webhook lag rather than guessing at it.
Invalidate dependent caches. On entitlement change, invalidate any cached queries whose results depend on tier (plan caps, squad caps, vault access, paywall copy).
Founding-vs-standard consistency. The store must expose which tier resolved (founding vs standard), not just a boolean, so that pricing surfaces stay consistent. See the separate Photo Vault prompt for the hardcoded-price bug.
Logout clears it. Entitlement state must be fully cleared on logout, consistent with the previously fixed stale-user-cache bleed. Verify a rapid logout → login as a different user cannot show the first user's tier.
