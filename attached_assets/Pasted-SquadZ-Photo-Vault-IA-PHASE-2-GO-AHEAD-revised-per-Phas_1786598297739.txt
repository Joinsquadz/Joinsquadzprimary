1. Close the roll-up entitlement gap — P0, do this first

POST /api/squads/:id/vault checks squad membership and photo ownership but performs no Squadz+ entitlement check. The gate today is only that the picker's source list (GET /api/vault/photos with no scope) returns requiresPro: true, so the UI can't populate. An authenticated caller who knows their own photo IDs bypasses it entirely.

Add the server-side entitlement check to POST /api/squads/:id/vault, matching how POST /api/vault/saves is already gated. Free-tier enforcement must not depend on the client failing to render a list.

Add a test asserting a free-tier user with valid membership and valid owned photo IDs is rejected by this endpoint.

Do not gate DELETE /api/squads/:id/vault/:photoId — removing your own media from a squad vault must stay available regardless of tier, or a lapsed subscriber can't retract their own photos.
