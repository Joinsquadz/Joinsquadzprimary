# Phase 2: Remove Leaked Google Cloud Credential From Git History (Implement)

**MODE: IMPLEMENT**

## Context

GitHub's push protection blocked the push to Joinsquadzprimary because commit `31d3f921abc027e7557700768a404137b1460942` contains a Google Cloud service account credentials file at `artifacts/squadz-native/squadz-service-account.json`. That key is being rotated on Google Cloud directly, separately from this work. This task is to get it out of the codebase and git history properly so the push can succeed and this can't happen again.

## Locked decisions

- Confirm what currently loads or references this file in code, search for the file path and any credential-loading pattern tied to it.
- Move credential loading to a Replit Secret, an environment variable, instead of a committed JSON file. If the code expects a file path, either write the secret's content to a temp file at runtime, or refactor to accept the credential JSON directly from the environment, whichever fits the existing pattern with the least change.
- Add `artifacts/squadz-native/squadz-service-account.json` to `.gitignore`, along with any similar credential file pattern already in use, so this can't be recommitted.
- Remove the file from git history entirely, not just delete it in a new commit, since a plain deletion would still leave it recoverable from history. Use `git filter-repo`, or an equivalent history rewriting tool, to strip it from every commit. This push has never succeeded before, so there's no other clone or fork depending on the current commit hashes, rewriting history here is safe.
- After rewriting history, confirm the file is genuinely gone from all commits, search full history, not just the current one.

## Required

- If anything currently depends on reading this file directly and can't be trivially switched to an environment based secret without more context, stop and report rather than guessing at the right fix.
- Run the full test suite after the change to confirm nothing broke.
- While in here, check whether there are any other committed secrets following the same pattern, better to find them now than hit another blocked push later.

## Output

Confirmation of what was found referencing this file, how credential loading was changed, confirmation the file no longer appears anywhere in git history, and test results. Once this comes back clean, the push to GitHub should be attempted again.
