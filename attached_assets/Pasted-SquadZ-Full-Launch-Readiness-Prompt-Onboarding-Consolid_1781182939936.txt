SECTION 1 — Onboarding Overhaul
The goal is to get every new user into a squad with at least one real friend before they see anything else in the app. The home screen is not a destination — a squad is.
Post-onboarding destination:
After completing onboarding — whether the user created a squad or joined one via invite — navigate them directly into that squad's detail screen, not the home tab. The squad screen is their first real experience of the app.
Welcome tips system:
Once inside the squad for the first time, surface a sequential tooltip system — a small floating card anchored to the relevant UI element that the user can dismiss by tapping the X or tapping Next. Tips should only appear once per user, ever. Store a hasSeenTips flag per user locally. The tip sequence is:

Tip 1 — anchored to the Events section: "Create your first event. Pick a date, add a location, and invite your crew."
Tip 2 — anchored to the availability poll: "Find a time everyone's free. Drop a poll and let your squad respond."
Tip 3 — anchored to the chat: "Talk it out. Every squad has its own group chat — no more lost plans in a group text."
Tip 4 — anchored to the cost split: "Split costs without the awkwardness. Log expenses and track who owes what."
Tip 5 — anchored to the Feed tab in the bottom nav: "Catch Moments here too. Squad Moments and Friends Moments both live in your feed ring row at the top."
Tip 6 — anchored to the bottom nav Feed tab: "See what your crew is up to. Post a Vibe to let your friends know you're free."

Each tip card should have: a short bold headline, one sentence of body copy, a Next button, and an X to dismiss the entire sequence early. The card should be small — maximum 220px wide, dark card surface (#1A1A1A), orange accent on the Next button. It should never block the element it is describing — anchor it above or below with an arrow indicator pointing to the relevant UI.
Onboarding flow cleanup:

If the user arrived via a squad invite link, skip the squad creation step entirely and take them directly into the invited squad after account creation, then begin the tip sequence
If the user created a new squad during onboarding, take them into that squad and begin the tip sequence
The first-run coach mark on the home screen ("New here? Create a squad…") should no longer appear — the onboarding now handles this context
Remove any remaining references to hobbies, interests, or any data collection that is not name, email, phone, or avatar


SECTION 2 — Moments and Vibe Feed Consolidation
Remove Moments from the squad detail screen entirely. Squad-scoped Moments ring rows should no longer appear at the top of any squad view. The squad screen returns to its original layout — chat, events, members, and tasks — with no Moments UI.
Moments live exclusively in the Vibe Feed tab going forward. The feed ring row at the top of the Vibe Feed is the only surface where Moments appear. This ring row already handles both Friends Moments and Squad Moments correctly — no changes needed to the ring row itself.
Changes required:

Remove MomentsRingRow mode="squad" from every squad detail screen
Remove any Moments composer entry point that is anchored to the squad view
The Moments composer should only be accessible from the Vibe Feed tab
When a user composes a Moment and selects a squad as the audience, the resulting Moment appears in the feed ring row — not in the squad screen. The audience scoping remains correct — only squad members see it — but the display surface is the feed ring row only
Verify no orphaned Moments UI remains in the squad tab after removal — no empty ring rows, no placeholder space, no broken imports

Verify:

Squad detail screen has no Moments UI on any squad, for any user type
Feed ring row correctly shows both Friends and Squad Moments
Composing a Moment from the feed correctly offers the audience picker (Friends or a specific squad)
A Squad Moment posted from the feed appears in the feed ring row and is visible only to that squad's members — not to non-members
No console errors related to removed Moments components in the squad view

SECTION 4 — Multi-User Simulation (8 Concurrent Users)
Create 8 test accounts with the following profiles and simulate all of them using the app simultaneously. The goal is to surface race conditions, SSE conflicts, notification failures, and data consistency issues that only appear under real multi-user load.
Test accounts:

User 1: Squad organizer, Squadz+ subscriber
User 2: Squad member, free user
User 3: Squad member, free user
User 4: Squad member, free user
User 5: Member of a different squad, free user
User 6: Friend of User 1 only, not in any shared squad
User 7: New user, just completed onboarding
User 8: Free user at the 2-squad limit

Simulate the following scenarios simultaneously:
Scenario A — Event coordination:
User 1 creates an event. Users 2, 3, and 4 RSVP simultaneously — going, maybe, no respectively. User 1 adds an event task and assigns it to User 2. User 2 marks it complete. Verify: RSVP counts are accurate for all users, task state syncs correctly, and User 1 receives all RSVP notifications without duplicates.
Scenario B — Live chat under load:
Users 1, 2, 3, and 4 send messages in the squad chat simultaneously. Verify: messages appear in the correct order for all users, no messages are dropped, SSE does not break under concurrent senders, and read receipts or indicators update correctly.
Scenario C — Vibe Feed concurrent posts and reactions:
User 1 posts a Vibe to Friends. User 6 reacts. User 2 posts a Vibe to the squad. Users 3 and 4 react simultaneously. Verify: reactions update in real time for all viewers of each post, audience scoping is correct (User 6 does not see the squad Vibe, User 5 does not see User 1's friends Vibe), and no reaction counts are lost due to race conditions.
Scenario D — Moments concurrent posts:
User 1 posts a Friends Moment. User 2 posts a Squad Moment to the shared squad from the Vibe Feed. User 7 (new user) views both ring rows in the feed. Verify: Friends Moment appears only in the feed ring row for friends of User 1, Squad Moment appears only in the feed ring row for squad members, ring seen/unseen state updates correctly per user, and expiry is tracked independently for each Moment. Confirm no Moments appear in any squad detail screen.
Scenario E — Upgrade and gate enforcement under load:
User 8 attempts to join a 3rd squad via three simultaneous methods — UI join, invite link, and direct API call. Verify: all three are blocked and the UpgradeModal appears for UI attempts, the API returns 403 for the direct call, and no race condition allows a momentary join before the limit check fires.
Scenario F — DM gate under concurrent messaging:
User 1 (Pro) sends a DM to User 2 (free) and User 3 (free) simultaneously. Verify: both free users receive a generic push notification with no message preview, both see blurred content in the inbox, and upgrading User 2 mid-session unlocks their inbox without affecting User 3's gated state.
Scenario G — SSE resilience:
While Scenarios A through F are running, simulate a network drop for User 3 and User 4 by killing their SSE connections. Verify: the reconnect banner appears for both users, tapping retry restores the stream, and they receive any messages or updates they missed during the drop once reconnected.
For every scenario report: what worked, what failed, any data inconsistencies, any duplicate notifications, and any race conditions observed.

SECTION 5 — Performance and Device Optimization
Network performance:

Simulate a slow 3G connection (throttle to approximately 1Mbps) and test: app load time, feed load time, photo vault load time, Moments upload, and chat message delivery. Note anything that feels unacceptably slow
Implement lazy loading on the Vibe Feed and photo vault if not already in place — images should not all load at once on scroll
Moments video upload should show a progress indicator — if it does not, add one
Any screen that loads data should show a skeleton loader, not a blank white or black screen, while content is fetching

Image optimization:

All user-uploaded photos in the feed and photo vault should be compressed and resized server-side before storage — original resolution uploads should not be served directly to clients
Avatars should be served at a maximum of 200x200px — larger avatars waste bandwidth on every screen they appear
Moments thumbnails in the ring row should be pre-generated at a small size — do not load full-resolution images for the ring row

Memory and performance:

Test the app after 15 minutes of continuous use — does memory usage grow unbounded or stabilize?
The Vibe Feed and squad chat should implement virtualized list rendering if not already — FlatList with proper keyExtractor and getItemLayout
SSE connections should be properly cleaned up when navigating away from a screen — verify there are no dangling connections accumulating in the background

Tablet and large screen:

Test every screen on an iPad or Android tablet equivalent at 768px width minimum
Navigation, cards, modals, and the feed should all respond correctly at larger sizes
The bottom nav should not stretch awkwardly on tablet — consider a sidebar nav layout on screens wider than 768px
Modals should be width-constrained on tablet — max 500px centered, not full-width
