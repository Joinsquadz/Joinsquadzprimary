Free tier — permanently limited by append-only counters:
Squads: free users can create or join a maximum of 2 squads total. Once the counter reaches 2 it never decreases under any circumstance — not on squad leave, squad delete, squad removal, or any other action. The counter is stored server-side and enforced at the API level.
Events created: free users can create a maximum of 3 events total. Once the counter reaches 3 it never decreases — not on event delete, event leave, or any other action. RSVPing to events created by others does not count toward this limit. Only the act of creating an event increments the counter.
Add two append-only columns to the users table:

squads_joined_total (integer, default 0)
events_created_total (integer, default 0)

Both counters must be implemented as atomic increments using the same pg_advisory_xact_lock pattern already used for squad limits. They must never decrement under any circumstance.

When a free user upgrades mid-session, all lock overlays disappear immediately without requiring a restart.

SECTION 2 — Unified Vault System
This is the core of the fluid content system. The goal is that photos and videos feel like they belong to the user, not just to a squad.
Two vault surfaces — both exist simultaneously:
1. Squad vault (existing, enhanced)

Every squad still has its own vault showing all media uploaded to that squad. This is the shared, collaborative view. All squad members with access can see, comment, heart, caption, and favorite items here.
2. Personal vault (new — accessible from profile)

A unified view of everything the user has personally uploaded across all squads, plus anything they have marked as a favorite from any squad vault. This is their personal media collection. It lives on their profile under a dedicated Vault tab alongside the existing Photos tab concept — consolidate these into one unified Vault tab since they serve the same purpose.
Vault tab on profile:

Replace the Photos tab concept from the previous spec with a single unified Vault tab on the profile screen. This tab contains two sub-sections accessible via a toggle or segmented control at the top:

My Uploads — every photo and video the user personally uploaded across all squads
Favorites — every photo and video the user has marked as a favorite from any squad vault, regardless of who uploaded it

Both sub-sections share the same filter bar and grid layout.
Filters — apply to both My Uploads and Favorites:

Horizontally scrollable filter bar above the grid, fully combinable:

All — photos and videos, most recent first (default)
Photos — images only
Videos — videos only
By Squad — chip selector showing all squads with content; selecting one filters to that squad
By Date — month/year picker
Favorited — shortcut to the Favorites sub-section from anywhere in the filter bar

Favorites mechanics:

Any user can mark any photo or video in any squad vault as a favorite by tapping a bookmark or star icon on the media item. Favorites are personal — they are visible only to the user who marked them. Favoriting does not notify anyone and does not move or copy the original file. It simply adds a reference to the user's personal Favorites collection.
A favorited item in the personal vault links back to the original in the squad vault — tapping it opens the full media detail view in the context of its squad.
Favorites are available to all users including free users. However, free users can only view favorites that are still within the 14-day window. Favorites older than 14 days show a lock overlay for free users, consistent with the vault visibility model. Upgrading to Squadz+ unlocks all favorited items permanently.

SECTION 3 — Vault Media Interactions: Comments, Hearts, Captions & Sharing
Every photo and video in every squad vault should support rich interactions. The goal is to make vault content feel alive and social without broadcasting anything outside the squad without intent.
Media detail view:

Tapping any photo or video in a squad vault opens a full-screen detail view. This view contains:

The photo or video (full screen, pinch to zoom on photos, play/pause on video)
The caption — displayed below the media, editable by the uploader at any time
Heart count and who hearted it (visible to all squad members with vault access)
Comments thread — visible to all squad members with vault access
Uploader name, avatar, squad name, and upload date
A favorite (bookmark) icon in the top right — tapping toggles the item in/out of the user's personal favorites
A share icon — tapping opens the share-to-Vibe flow
An options menu for the uploader: edit caption, delete

Captions:

Captions can be added at upload time or after upload. They are editable by the uploader at any time. Captions have a 300 character limit. They are visible to all squad members with access to that vault item.
Hearts:

Any squad member with vault access can heart a photo or video. Hearts are visible to all squad members — the count is shown below the media and tapping the count shows a list of who hearted it. Hearts are real-time via the existing SSE infrastructure. Hearting a vault item does not post anything to the Vibe Feed or notify anyone outside the squad.
Comments:

Any squad member with vault access can comment on a photo or video. Comments are threaded and real-time via SSE. Comments are visible only to squad members with access to that vault item — they never appear in the Vibe Feed or any surface outside the vault. The uploader receives a push notification when someone comments on their photo. Comment notifications deep link to the media detail view.
Share to Vibe:

Any user can share any vault item they have access to directly to their Vibe Feed. The share flow works as follows:

User taps the share icon on a media item
A composer opens — similar to the Vibe post composer but pre-populated with the photo or video
The user can type a status or caption for the Vibe post — this is optional but encouraged with placeholder copy: "Add a caption for your friends..."
Audience is locked to Friends only — the user cannot change this to a squad. This is intentional: squad content shared to the feed goes to friends, not back into a squad context.
User taps Post — the item appears in their friends' Vibe Feed as a standard Vibe post with the photo/video and their caption
The original vault item is unchanged — sharing creates a new Vibe post, it does not move or remove the item from the vault

The share flow should feel like Facebook's share mechanic — you see the content, you add your words, you post. Fast and fluid.
Sharing to Vibe is available to all users including free users as long as the item is within its 14-day visibility window. Free users cannot share locked items — tapping share on a locked item opens the UpgradeModal with photo_vault trigger.

SECTION 5 — 14-Day Vault Expiry Notifications
Notification sequence:

For every photo or video batch uploaded by a free user, schedule three push notifications. A batch is all media uploaded to the same squad within a 6-hour window — one notification per squad per window.

Day 10: "📸 Your [squad name] photos expire in 4 days. Upgrade to Squadz+ to keep them forever."
Day 13: Dynamic — if founding spots remain: "⏰ Your [squad name] photos disappear tomorrow. Founding member pricing still available — only X spots left." If founding gone: "⏰ Your [squad name] photos disappear tomorrow. Upgrade now — $29.99/year."
Day 14: "Your photos from [squad name] are now locked. Upgrade to Squadz+ to restore access instantly."

Each notification deep links to UpgradeModal with trigger photo_vault.
Notification rules:

User upgrades before notification fires — cancel all pending expiry notifications
Never send to Squadz+ users
User deletes photos before expiry — cancel remaining notifications for that batch
Maximum one expiry notification per day per user
